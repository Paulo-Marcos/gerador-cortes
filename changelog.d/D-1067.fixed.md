- **Tagging a release no longer breaks on long release notes.** The 0.7.0 tag
  message reached 76,202 characters and went to `git tag` as a `-m` argument,
  which Windows refuses above about 32 thousand (WinError 206): every check had
  passed and the tag had to be created by hand. `bin/release.py` now writes the
  message to a temporary file, passes it with `-F` (still `--cleanup=verbatim`,
  so the `### Added` headings stay) and deletes the file at the end; long
  arguments are shortened in the script's log instead of printed whole. A
  breaking change is now declared only by the explicit `**BREAKING**` marker:
  the bare word "breaking" in an entry, as in the Pillow 13 fix (D-982), no
  longer counts, so from 1.0 on it cannot force a major (D-1067).
