- **Coding agents may now delete the database copies left in worktrees, while
  production and the main tree stay locked.** The deny list in
  `.claude/settings.json` blocked every `*.db` relative to the session folder.
  That stopped an agent from removing the production copies it had placed in a
  worktree for screenshots, and those copies had already broken a ship. The same
  relative pattern never reached production from a worktree session.

  The new rules use absolute paths:
  - **Production (`C:\PRD`) is fully denied.** That includes code and logs, so
    an agent session can read nothing there. Opening it up takes an edit to
    this file.
  - **The main tree's `instance/` is fully denied.**
  - **Databases elsewhere in the main tree are denied** at its root, in every
    top-level folder and in `.claude`, together with the SQLite `-wal` and
    `-shm` files. A test requires a rule for every tracked folder and for the
    known ignored ones.
  - **The `.db` files under `.claude/worktrees` are free.**

  These rules also stop `rm`, `mv`, `cp` and `cat`. They do not stop an
  interpreter: `python -c` or a script can still read or delete a denied file.
  The deny list holds back the usual path, not a sandbox.

  `.env`, `token.json` and `client_secrets.json` are now also denied on any
  drive, so the main tree's `backend/.env` is no longer readable from a worktree
  session. The relative secret rules, `~/.ssh` and `~/.aws` stay as they were
  (D-1156).
